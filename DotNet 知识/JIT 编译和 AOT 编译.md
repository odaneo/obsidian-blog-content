
## JIT 编译（即时编译）灵活

- **JIT**（Just-In-Time）编译是把代码在运行时转换成机器码。
- 代码在执行时才被编译，不需要预先编译。
- 优点：灵活，支持各种平台。
- 缺点：启动时会有编译延迟。
- 在运行时将 IL 代码编译为本地机器码。JIT 编译是平台依赖的，因此需要为每个平台提供相应的编译器。

## AOT 编译（预编译）性能好

- AOT（Ahead-Of-Time）编译是在编译时就把代码转换成机器码。
- 应用程序发布时，所有代码已被编译成目标平台的机器码。
- 优点：启动更快，运行时不需要编译。
- 缺点：没有 JIT 灵活，可能需要更多的存储空间。
- 对于某些性能关键的应用，.NET Core 还可以使用 AOT 编译，将代码在构建时预先编译为目标平台的本地代码。这可以减少启动时间和运行时开销。

| 场景 | 推荐 |
| --- | --- |
| 云服务，服务器部署 | JIT（默认） |
| 容器镜像，追求启动时间 | AOT |
| 桌面应用（WinForms/WPF） | JIT（但也能 AOT） |
| 移动端 / IoT 设备（如 iOS） | AOT |
