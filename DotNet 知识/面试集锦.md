

### Q1：什么是扩展方法？

**A：**  
扩展方法就是“在不修改原类型、不继承原类型的情况下，给已有类型增加方法”。  
它必须定义在静态类里，方法是静态方法，第一个参数加 `this`。

**例子：**

```csharp
public static class StringExtensions
{
    public static int ToIntOrDefault(this string s, int defaultValue = 0)
    {
        return int.TryParse(s, out var v) ? v : defaultValue;
    }
}

// 使用
int n = "123".ToIntOrDefault(); // 123
int m = "abc".ToIntOrDefault(10); // 10
```

**注意：**  
如果原类型已经有同名实例方法，会优先调用实例方法，扩展方法不会被调用。

---

### Q2：什么情况下使用扩展方法？

**A：**  
常见场景：

1. 不能改源码，比如第三方库、系统类型。
2. 不想继承，只想加个小工具方法。
3. 给接口加通用能力，比如 `IEnumerable<T>`。
4. 写 LINQ 风格的工具方法。

**例子：**

```csharp
public static class EnumerableExtensions
{
    public static bool IsEmpty<T>(this IEnumerable<T> source)
    {
        return !source.Any();
    }
}

// 使用
var list = new List<int>();
bool empty = list.IsEmpty(); // true
```

**注意：**  
不要滥用。尤其是给业务类加一堆扩展方法，容易让代码难找、难维护。

### Q3：C# 有没有内存泄漏？

**A：**  
有。  
GC 只负责回收“不可达”的托管对象。如果对象已经不用了，但仍然被引用，GC 就回收不了，这就是托管内存泄漏。  
另外，非托管资源不释放，也会造成泄漏，比如文件句柄、数据库连接、GDI 对象等。

**例子 1：静态集合导致泄漏**

```csharp
public static class Cache
{
    public static readonly List<object> Items = new List<object>();
}

// 一直加，永远可达，GC 不回收
Cache.Items.Add(new object());
```

**例子 2：事件未取消订阅**

```csharp
publisher.Changed += subscriber.OnChanged;

// 如果 publisher 生命周期比 subscriber 长，
// 且不取消订阅，subscriber 会一直被 publisher 引用，无法回收
```

**例子 3：非托管资源未释放**

```csharp
var fs = new FileStream("a.txt", FileMode.Open);
// 不 Dispose，文件句柄可能泄漏
```

### Q4：C# 内存回收机制是什么？

**A：**  
C# 靠 GC 自动回收托管堆内存。  
GC 从根对象开始找“可达对象”，不可达的就被回收。  
它采用分代回收：0 代、1 代、2 代，还有大对象堆 LOH。  
非托管资源 GC 管不了，要用 `IDisposable`、`Dispose()`、`using` 手动释放。

**例子：**

```csharp
using (var fs = new FileStream("a.txt", FileMode.Open))
{
    // 用完自动 Dispose，释放文件句柄
}
```

或者：

```csharp
using var fs = new FileStream("a.txt", FileMode.Open);
```

**注意：**  
不要随便手动 `GC.Collect()`，一般交给 GC 自己处理。

### Q7：C# 调用 C# 函数，参数是 class 时怎么传？

**A：**  
C# 默认都是**按值传递**。  
如果参数是 `class`，传的是“对象引用的副本”。  
所以：

- 方法里改对象属性，会影响原对象。
- 方法里把参数重新赋值为新对象，不影响调用方。
- 想改变调用方变量本身，要用 `ref` 或 `out`。

**例子：**

```csharp
class Person
{
    public string Name { get; set; }
}

static void Change(Person p)
{
    p.Name = "Tom";                    // 影响原对象
    p = new Person { Name = "Jerry" }; // 只改副本，不影响调用方
}

var p = new Person { Name = "Alice" };
Change(p);

Console.WriteLine(p.Name); // Tom
```

如果用 `ref`：

```csharp
static void Replace(ref Person p)
{
    p = new Person { Name = "Jerry" };
}

Replace(ref p);
Console.WriteLine(p.Name); // Jerry
```

### Q8：如果是值传递过程中改变对象的属性值，会有什么问题？

**A：**  
如果对象是 `class`，虽然是按值传递，但传的是引用副本，所以改属性会改到原对象。  
这容易造成意外副作用：调用方以为没改，结果原对象被改了。

**例子：class 会被改**

```csharp
class Person
{
    public string Name { get; set; }
}

static void Modify(Person p)
{
    p.Name = "Bob";
}

var p = new Person { Name = "Alice" };
Modify(p);

Console.WriteLine(p.Name); // Bob
```

**如果是 struct：**

```csharp
struct Point
{
    public int X;
}

static void Modify(Point p)
{
    p.X = 10;
}

var pt = new Point { X = 1 };
Modify(pt);

Console.WriteLine(pt.X); // 1，改的是副本
```

**但 struct 里如果有引用类型字段，仍然可能改到原对象：**

```csharp
class Box
{
    public int Value;
}

struct Holder
{
    public Box Box;
}

static void Modify(Holder h)
{
    h.Box.Value = 100; // h 是副本，但 Box 是引用，原对象被改
}

var box = new Box { Value = 1 };
var holder = new Holder { Box = box };

Modify(holder);
Console.WriteLine(box.Value); // 100
```

**面试总结：**  
`class` 默认传引用副本，改属性会影响原对象；重新赋值参数不影响调用方。  
`struct` 默认传值副本，改字段不影响原变量；但如果字段是引用类型，改该引用对象的属性仍会影响原对象。

### Q1：`ref`、`out`、`in` 有什么区别？

**A：**  
它们都是引用传递，但规则不同：

| 修饰符 | 进入前是否必须初始化 | 方法内能否修改 | 调用时是否要写 | 用途 |
|---|---|---|---|---|
| `ref` | 必须 | 可以读、可以写 | 必须写 `ref` | 把变量传进去，方法可能改它 |
| `out` | 可以不初始化 | 必须赋值后才能读 | 必须写 `out` | 方法负责输出值 |
| `in` | 必须 | 不能修改参数本身 | 可写可不写 | 只读引用，避免大结构体拷贝 |

**例子：**

```csharp
void RefTest(ref int x)
{
    x++; // 可以改
}

void OutTest(out int x)
{
    x = 10; // 必须赋值
}

void InTest(in int x)
{
    // x = 1; // 编译错误，不能改
    Console.WriteLine(x);
}

int a = 1;
RefTest(ref a); // a = 2

OutTest(out int b); // b = 10

int c = 5;
InTest(in c); // 也可以写成 InTest(c)
```

**面试速答：**  
`ref` 有进有出，`out` 只出不进，`in` 只进不出。

### Q4：`Task` 和 `async/await` 区别？

**A：**  
`Task` 是“异步操作的对象”，表示一个可能完成、失败、取消的操作。  
`async/await` 是“写异步代码的语法糖”，让你像写同步代码一样写异步。

- `Task`：做什么。
- `async/await`：怎么写。
- `async` 方法通常返回 `Task`、`Task<T>` 或 `ValueTask`。
- `await` 等待 `Task` 完成，但不会阻塞当前线程。

**例子：**

```csharp
public async Task<string> GetDataAsync()
{
    var data = await httpClient.GetStringAsync("https://example.com");
    return data;
}
```

上面：

- `GetStringAsync` 返回 `Task<string>`。
- `await` 等它完成。
- 当前线程不会被卡死。
- 方法声明成 `async Task<string>`。

**面试速答：**  
`Task` 是异步结果，`async/await` 是简化异步编程的语法。

### Q5：`Task` 和 `Thread` 的区别？

**A：**  
`Thread` 是操作系统线程，创建、销毁开销大，数量有限，要手动管理。  
`Task` 是更高级的抽象，默认跑在线程池上，支持返回值、异常、取消、延续、组合，更轻量。

**例子：**

```csharp
// Thread
Thread t = new Thread(() => Console.WriteLine("Thread"));
t.Start();

// Task
Task.Run(() => Console.WriteLine("Task"));
```

区别总结：

- `Thread`：直接对应 OS 线程。
- `Task`：任务抽象，不一定新开线程。
- `Task` 更适合现代异步、并行代码。
- 只有需要长时间运行、专用线程时才考虑直接 `new Thread`。

**面试速答：**  
`Thread` 是线程，`Task` 是任务。现代 C# 优先用 `Task`。

### Q7：委托和事件有什么区别？

**A：**  
委托是类型安全的函数指针，可以赋值、`+=`、`-=`、调用。  
事件是基于委托的封装，外部只能 `+=`、`-=`，不能直接赋值，也不能直接调用；只能在声明它的类内部触发。

**例子：**

```csharp
public delegate void MyHandler(string msg);

public class Publisher
{
    public event MyHandler Changed;

    public void Raise()
    {
        Changed?.Invoke("hello"); // 只能在类内部触发
    }
}

var p = new Publisher();

p.Changed += msg => Console.WriteLine(msg);

// p.Changed = null;       // 编译错误
// p.Changed("test");      // 编译错误
```

**面试速答：**  
委托是类型，事件是委托的受控封装。  
事件对外只开放订阅和取消订阅，触发权在类内部。

### Q1：数据库连接池释放原理是什么？是否用到垃圾回收？为什么？

**A：**  
连接池的“释放”不是真的关闭物理连接，而是**把连接归还给池子**。  
调用 `SqlConnection.Close()` 或 `Dispose()` 时，底层通常把连接状态重置，然后放回空闲连接池，下次还能复用。

**用不用 GC？**  
基本不用。连接池自己持有物理连接的强引用，GC 不会回收它们。  
归还连接靠的是显式 `Close/Dispose`，不是 GC。  
如果忘记释放，连接会一直被池子占着，可能导致连接池耗尽。虽然 GC 最终可能通过终结器兜底，但不可靠、不及时。

**例子：**

```csharp
using (var conn = new SqlConnection(connStr))
{
    conn.Open();
    // 用完自动 Dispose，连接归还池子，而不是物理关闭
}
```

**面试速答：**  
连接池释放是“归还”，不是“销毁”。靠 `Dispose/Close`，不靠 GC。GC 管不了池子里的物理连接。

### Q3：`using` 里面用到哪些固定类型？工作原理和机制是什么？内存中发生了什么？

**A：**  
不是固定类型，而是必须实现：

- `IDisposable`：同步释放
- `IAsyncDisposable`：异步释放

常见类型：`SqlConnection`、`FileStream`、`StreamReader`、`Timer`、`HttpClient`（但通常不建议 using，因为要复用）等。

**工作原理：**  
编译器把 `using` 展开成 `try/finally`，在 `finally` 里调用 `Dispose()`。

```csharp
using (var fs = new FileStream("a.txt", FileMode.Open))
{
    // 使用 fs
}
```

等价于：

```csharp
FileStream fs = null;
try
{
    fs = new FileStream("a.txt", FileMode.Open);
    // 使用 fs
}
finally
{
    if (fs != null)
        fs.Dispose();
}
```

**内存中发生了什么：**

- 对象分配在托管堆。
- `Dispose()` 释放的是非托管资源，比如文件句柄、数据库连接、GDI 对象。
- 托管内存本身不会立刻回收，要等 GC。
- `Dispose()` 后一般会调用 `GC.SuppressFinalize(this)`，告诉 GC 不用再走终结器。

**面试速答：**  
`using` 只认 `IDisposable/IAsyncDisposable`，编译成 `try/finally` 调 `Dispose`。释放非托管资源，不立即释放托管内存。

### Q4：`using` 里面可以用多线程吗？如何实现？

**A：**  
可以，但必须保证：**离开 `using` 块之前，所有线程都用完了这个对象**。  
否则 `using` 结束调用 `Dispose`，其他线程还在用，就会 `ObjectDisposedException`。

**正确例子：等所有任务完成再离开 using**

```csharp
using (var client = new HttpClient())
{
    var tasks = new[]
    {
        client.GetStringAsync("https://a.com"),
        client.GetStringAsync("https://b.com")
    };

    var results = await Task.WhenAll(tasks);
    // 所有任务完成后，才离开 using，Dispose 才安全
}
```

**错误例子：**

```csharp
using (var client = new HttpClient())
{
    Task.Run(() => client.GetStringAsync("https://a.com"));
}
// using 结束就 Dispose，后台任务可能还在用，抛异常
```

**多线程实现方式：**

- `Task.Run`
- `Thread`
- `Parallel.For/ForEach`
- `async/await` + `Task.WhenAll`

**原则：**  
同一个 `Disposable` 对象不要被多个线程同时乱用。  
要么每个线程用自己的实例，要么加锁，要么等所有线程结束再释放。

### Q5：`List` 和 `Dictionary` 哪个性能高？`for` 循环下哪个性能高？为什么？

**A：**  
没有绝对，看操作：

| 操作 | List | Dictionary |
|---|---|---|
| 按索引访问 | O(1)，非常快 | 不支持 |
| 按键查找 | O(n) | O(1) 平均 |
| 遍历所有元素 | 快，连续内存 | 较慢，哈希桶不连续 |
| 插入 | 尾部均摊 O(1) | 平均 O(1) |
| 内存占用 | 小 | 大，有哈希桶和空位 |

**`for` 循环下：**

- 如果只是遍历所有元素，`List` 更快。  
  因为 `List` 底层是数组，连续内存，CPU 缓存友好，`for` 按索引访问非常快。

```csharp
for (int i = 0; i < list.Count; i++)
{
    var item = list[i]; // O(1)
}
```

- `Dictionary` 不能用 `for` 按索引遍历，只能 `foreach`。  
  遍历的是哈希桶，顺序不保证，内存不连续，通常比 `List` 慢。

```csharp
foreach (var kv in dict)
{
    // 遍历哈希桶
}
```

- 但如果循环里要**根据 key 查找**，`Dictionary` 远快于 `List`。  
  `List` 查找是 O(n)，`Dictionary` 平均 O(1)。

**面试速答：**  
遍历用 `List`，查找用 `Dictionary`。`for` 循环遍历 `List` 性能高，因为连续内存、索引 O(1)；`Dictionary` 遍历慢，但按键查找快。
