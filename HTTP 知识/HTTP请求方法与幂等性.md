请求方法说明客户端希望怎样操作资源。安全性和幂等性描述的是方法的预期语义。

| 方法 | 主要用途 | 安全 | 幂等 |
| --- | --- | --- | --- |
| GET | 读取资源 | 是 | 是 |
| HEAD | 获取与GET对应的响应头，不返回响应体 | 是 | 是 |
| OPTIONS | 查询通信选项，常用于CORS预检 | 是 | 是 |
| POST | 提交数据，由目标资源处理，例如创建订单 | 否 | 不保证 |
| PUT | 创建或整体替换目标资源的表示 | 否 | 是 |
| PATCH | 按补丁描述修改资源 | 否 | 不保证 |
| DELETE | 删除目标资源 | 否 | 是 |

## 安全性看是否要求修改状态

GET等安全方法不要求改变资源状态，但服务器仍可以记日志、统计访问次数。因此，“安全”不表示执行过程完全没有副作用。

## 幂等性看重复请求的效果

同一个请求执行多次，对服务器产生的预期效果与执行一次相同，就具有幂等性。

例如，删除一个用户后再次删除，用户仍处于已删除状态。第一次可能返回204，第二次返回404，响应不同并不影响删除操作的幂等性。[HTTP方法语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2)

PATCH是否幂等取决于具体操作：将库存设为10，重复执行仍是10；将库存加1，每次执行都会继续增加。[PATCH规范](https://www.rfc-editor.org/rfc/rfc5789.html#section-2)

POST可以通过业务唯一键和服务端去重实现幂等，但方法本身不作保证。
