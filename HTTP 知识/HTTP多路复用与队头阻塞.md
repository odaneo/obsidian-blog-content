浏览器加载页面时，往往要请求HTML、样式和图片。多路复用允许这些请求和响应在同一条连接中交错传输。

HTTP/2使用TCP连接，HTTP/3使用基于UDP的QUIC连接。

## HTTP/1.1怎样并发

HTTP/1.1可以复用连接，也可以通过多条连接并发请求。

在单条连接中，流水线允许连续发送请求，但响应必须按请求顺序返回。前面的响应迟迟没有完成，后面的响应就需要等待，这属于HTTP层的队头阻塞。[HTTP/1.1连接管理](https://www.rfc-editor.org/rfc/rfc9112.html#section-9.3.2)

## HTTP/2怎样区分请求

HTTP/2把消息拆成帧，每次请求与响应对应一个流，用Stream ID区分。不同流的帧可以交错传输，再按流分别组装：

```text
同一连接中的帧：A1 → B1 → A2 → C1 → B2
```

B或C的响应可以先于A完成，从而避免HTTP/1.1中响应必须排队的问题。[HTTP/2流与多路复用](https://www.rfc-editor.org/rfc/rfc9113.html#section-5)

## HTTP/3解决哪一层阻塞

TCP按顺序向上交付字节。前面的数据丢失时，后面的数据即使已到达，也可能等待重传，因此HTTP/2中的多个流仍会一起受影响。

QUIC按流保证数据有序，一条流缺少数据时，其他流已收到的数据仍可继续交付。HTTP/3因此避免了TCP带来的跨流队头阻塞；各流仍共享网络带宽，整体性能也受拥塞和服务器处理速度影响。[HTTP/3规范](https://www.rfc-editor.org/rfc/rfc9114.html#section-1.1)
