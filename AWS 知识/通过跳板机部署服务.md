
## 一、准备访问条件

沿用两段SSH连接：

```text
本地 → 跳板机 → 私网EC2 → RDS
```

本地持有跳板机的`bastion.pem`，跳板机上持有私网EC2的`ec2.pem`。两段SSH都需要连通，私网EC2也要能访问RDS的3306端口。

下面以MySQL兼容数据库为例。本地使用15432作为转发端口，这个数字只是入口端口，不代表数据库使用PostgreSQL。

## 二、建立数据库隧道

### 本地连接跳板机

在本地执行：

```bash
ssh -i "bastion.pem" \
  -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:15432:127.0.0.1:15432 \
  ubuntu@BASTION_PUBLIC_IP
```

本地的`127.0.0.1:15432`会转发到跳板机的同一端口。保持这条连接打开，接着在跳板机里建立第二段隧道。

### 跳板机连接私网EC2

```bash
ssh -i "ec2.pem" \
  -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:15432:RDS_ENDPOINT:3306 \
  ubuntu@PRIVATE_EC2_IP
```

这次的本地端口位于跳板机。流量经过SSH交给私网EC2，再由EC2连接RDS。

两条连接保持期间，完整路径是：

```text
本地127.0.0.1:15432
    ↓
跳板机127.0.0.1:15432
    ↓
私网EC2
    ↓
RDS_ENDPOINT:3306
```

`-L`的目标连接从SSH远端发起；`-N`表示只转发端口，不执行远程命令。[SSH端口转发](https://man.openbsd.org/ssh#L)

### 本地执行数据库迁移

在另一个本地终端中，为EF Core迁移工具或SeedData程序配置连接字符串：

```text
Server=127.0.0.1;Port=15432;Database=your_db;User Id=your_user;Password=your_password;
```

确认目标数据库后，在项目目录执行：

```bash
dotnet ef database update
```

本地程序访问15432，最终连接的是RDS的3306。迁移结束后，可以关闭两条SSH连接。

## 三、传送发布文件

### 本地打包

在项目目录生成发布文件：

```bash
dotnet publish -c Release -o ./publish
```

后面的传输也从`./publish`读取，避免打包目录和上传目录不一致。目标EC2需要安装与应用匹配的.NET运行时；存在平台相关依赖时，也要使用适合目标Linux系统的发布配置。

### 上传到跳板机

准备专门存放本次发布包的空目录`~/temp_publish/`，再从本地上传：

```bash
ssh -i "bastion.pem" ubuntu@BASTION_PUBLIC_IP "mkdir -p ~/temp_publish"
scp -i "bastion.pem" -r ./publish/. ubuntu@BASTION_PUBLIC_IP:~/temp_publish/
```

SCP覆盖同名文件，但不会删除旧版本独有的文件。重复发布前，要先清理这个暂存目录中的旧包内容。

### 跳板机传到私网EC2

在跳板机执行：

```bash
rsync -av --delete -e "ssh -i ec2.pem" \
  ~/temp_publish/ ubuntu@PRIVATE_EC2_IP:~/myapp_new/
```

然后登录私网EC2，将暂存文件同步到应用目录：

```bash
rsync -av --delete ~/myapp_new/ ~/myapp/
```

`--delete`会删除目标目录中源端没有的文件，因此这些目录只用于对应的发布内容。日志等运行数据放在发布目录之外。

这是覆盖现有目录的部署方式。后续更新应先停止已有的`myapp.service`，同步文件后再启动；首次部署则先完成下面的服务配置。

## 四、配置systemd服务

在私网EC2创建服务文件：

```bash
sudo nano /etc/systemd/system/myapp.service
```

示例配置如下：

```ini
[Unit]
Description=MyApp .NET API
After=network.target

[Service]
WorkingDirectory=/home/ubuntu/myapp
ExecStart=/home/ubuntu/.dotnet/dotnet /home/ubuntu/myapp/myapp.Server.dll
Restart=always
User=ubuntu
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=DOTNET_ROOT=/home/ubuntu/.dotnet
Environment=PATH=/home/ubuntu/.dotnet:/home/ubuntu/.dotnet/tools:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

[Install]
WantedBy=multi-user.target
```

`ExecStart`中的运行时和DLL路径必须与实际安装一致。测试环境可把`Production`改为`Staging`，同一配置中保留一个环境值即可。[ASP.NET Core的systemd配置](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/linux-nginx#monitor-the-app)

首次加载并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now myapp.service
sudo systemctl status myapp.service
```

更新发布文件后重启：

```bash
sudo systemctl restart myapp.service
```

修改了服务文件时，先执行`daemon-reload`再重启。服务文件名、启动命令和日志查询均使用`myapp.service`。

查看运行日志：

```bash
sudo journalctl -u myapp.service -f
```

查询5000端口的监听情况：

```bash
sudo ss -tulpn | grep 5000
```

端口有监听只说明进程已经接收连接，还要结合应用日志与实际请求确认服务状态。

## 五、采集CloudWatch日志

先让应用通过Serilog等组件输出到`/var/log/myapp/myapp-*.log`。目录需要存在，应用要有写入权限，CloudWatch Agent要有读取权限。

EC2上安装并配置CloudWatch Agent，实例角色也应具备相应的日志上传权限。[Agent配置说明](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/Install-CloudWatch-Agent.html)

把以下内容保存为`/opt/aws/amazon-cloudwatch-agent/etc/cloudwatch-agent.json`：

```json
{
  "logs": {
    "logs_collected": {
      "files": {
        "collect_list": [
          {
            "file_path": "/var/log/myapp/myapp-*.log",
            "log_group_name": "/aws/ec2/myapp",
            "log_stream_name": "{instance_id}",
            "timestamp_format": "%Y-%m-%dT%H:%M:%S.%fZ",
            "timezone": "UTC"
          }
        ]
      }
    }
  }
}
```

这份配置假定日志使用相应的UTC时间格式。日志开头的时间戳不同，就调整`timestamp_format`；JSON内部不添加注释。[日志字段说明](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-Agent-Configuration-File-Details.html)

加载配置并启动Agent：

```bash
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
  -a fetch-config -m ec2 -s \
  -c file:/opt/aws/amazon-cloudwatch-agent/etc/cloudwatch-agent.json
```

`fetch-config`负责读取配置，`-s`启动Agent。配置完成后，发起一次应用请求，再到`/aws/ec2/myapp`日志组核对对应实例的日志流。[启动Agent](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/start-CloudWatch-Agent-on-premise-SSM-onprem.html)
