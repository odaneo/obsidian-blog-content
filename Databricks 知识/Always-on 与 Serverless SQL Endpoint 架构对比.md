| 特性               | **Always-on SQL Endpoint**                         | **Serverless SQL Endpoint**    |
| ---------------- | -------------------------------------------------- | ------------------------------ |
| **集群管理**         | 需要用户指定集群大小、伸缩范围                                    | 完全托管，无需配置                      |
| **启动时间**         | 冷启动几十秒~几分钟                                         | 秒级启动（即开即用）                     |
| **伸缩能力**         | 受限于用户设定的 scaling range                             | 自动扩缩，按需分配                      |
| **性能**           | 并发多时可能拥堵                                           | 自动扩容，低延迟                       |
| **费用**           | 长期开着会持续消耗 DBUs                                     | 按查询实际资源消耗计费，更节省                |
| **Auto Stop 功能** | ✅ 有，空闲后自动关闭，减少费用                                   | ❌ 没有（因为不需要停机，Databricks 资源池托管） |
| **使用场景**         | - 固定负载<br>- 需要精细控制集群大小<br>- 可配合 **Auto Stop **节省成本 | - BI 报表- 高频交互式查询- 高并发小查询场景     |
| **灵活性**          | 人工调参，灵活性低                                          | 全自动，用户只管写 SQL                  |

**SQL Endpoint 主要用于运行 SQL 查询**，而非执行 Spark 程序、ETL 流程或 Notebook 任务。其本质上是 Databricks 在底层 Spark Cluster 之上封装的一层 SQL 服务，使用户能够以 SQL 语言直接访问和分析数据，而无需关心底层 Spark 的复杂性。

### Serverless 的作用

- 主要解决：
	- **冷启动延迟**（endpoint 没运行时，要先启动 → 慢；Serverless 随时可用）。
	- **资源自动管理**（不需要你指定集群大小，Databricks 自动分配）。
- 不直接解决：
	- 高并发下的吞吐量瓶颈。
	- 因为 Serverless 还是有并发限制（底层也需要资源池），如果同时有大量小查询，可能还是会排队。
