| 特性 | **Job Cluster** | **All-purpose Cluster** | **Cluster Pool** |
| --- | --- | --- | --- |
| **用途** | 专门为一次性任务/**定时**作业创建 | 用于交互式开发（notebooks, ad-hoc queries） | 用来减少集群启动时间（预热资源池） |
| **生命周期** | 每次 Job 运行时创建，结束后**自动**销毁 | **手动**启动/停止，可能长时间运行 | 本身不是执行集群，而是虚拟机池，供其他集群借用 |
| **成本控制** | 不会闲置浪费，任务结束即释放 | 如果忘了关，可能产生高额费用 | 节省启动时长，但 pool 本身会产生基础成本 |
| **启动时间** | 较慢（每次都要新建 VM） | 较慢（同样需要启动 VM） | 快（集群直接复用 pool 中的预启动实例） |
| **适用场景** | - 定时批处理作业- ETL pipeline | - 数据科学家交互式分析- Notebook 调试 | - 任何频繁启动/销毁集群的场景（加速 job cluster 启动） |
| **运维复杂度** | 低，自动清理 | 中，需要手动管理运行时长 | 中，需要配置 pool 大小和闲置策略 |

Cluster 本质上是 Spark 集群。若需要**运行 Spark 代码、执行 ETL 流程、开发 Notebook 或进行机器学习任务**，通常会直接创建并使用 Cluster 来完成，而无需通过 Databricks 将其封装为 SQL Endpoint。
